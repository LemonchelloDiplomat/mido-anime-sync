# Надёжная локальная библиотека

**Приоритет:** P1 / основной фундамент проекта  
**Рабочая ветка:** `feature/pr-36-reliable-local-library`

## Цель

Локальная библиотека должна быть надёжным источником данных. Импорт, синхронизация, объединение дублей, очистка и восстановление не должны незаметно терять пользовательские записи, прогресс, оценки, избранное, связи с провайдерами или историю незавершённых операций.

Этот документ фиксирует текущую базу и план аудита/доработки. Наличие функции в коде не считается доказательством её полной надёжности, пока не проверены ошибки, миграции и сквозные сценарии на копии пользовательской базы.

## Уже реализовано в main

- IndexedDB-репозиторий с отдельными хранилищами аниме, агрегированных записей, source entries, разрешений конфликтов и связей между тайтлами.
- Миграции IndexedDB до версии 7, включая хранилища журнала операций, сессий и намерений удаления.
- Атомарные транзакции для ряда связанных изменений библиотеки.
- Раздельное хранение исходных записей провайдеров и построение агрегированной локальной записи.
- MAL и AniList: импорт и двусторонняя синхронизация; Shikimori: импорт и операции обновления/удаления.
- Provider baselines, планирование синхронизации, разрешение конфликтов и защита от части опасных удалений.
- Проверки, не позволяющие продвигать baseline после неудачного локального сохранения или неразрешённого конфликта.
- Журнал операций и сессий синхронизации, сохранение плана до выполнения записей и восстановление незавершённых операций по фактическому состоянию провайдера.
- Snapshot validation, экспорт/импорт и атомарный restore; при восстановлении незавершённые операции и затронутые сессии обезвреживаются, история операций/сессий сохраняется.
- Поиск потенциальных дублей по точным общим внешним ID; совпадения только по названиям намеренно не считаются достаточным доказательством.
- Слияние части связанных сущностей: внешних ID, названий, source entries, агрегированных записей, конфликтных решений и отношений между тайтлами.

## Дополнительные проверки вне блокеров PR #36

Чтобы не превращать завершение ветки в бесконечный аудит, дополнительные проверки отделены от обязательной готовности:

- Проверка OAuth и записи на реальные аккаунты MAL, AniList и Shikimori. Не запускалась автоматически, поскольку она меняет удалённые списки пользователя.
- Нагрузочный прогон на библиотеке существенно больше текущей тестовой копии.
- Проверка восстановления после искусственно смоделированного отказа браузерного хранилища посреди транзакции.
- Дополнительная проверка отдельных браузерных профилей.

Эти пункты можно выполнять отдельно при необходимости. Они не требуют расширять текущий PR новыми наборами однотипных тестов.

## Критерии готовности

- Ни один тестовый сценарий merge не теряет данные, внешние ID или связи.
- Неоднозначные дубли не объединяются автоматически.
- Повторные импорт, merge и restore идемпотентны.
- Сбой синхронизации не создаёт ложный успех и не продвигает baseline преждевременно.
- Восстановление snapshot выполняется одной IndexedDB-транзакцией; проверены восстановление поверх существующей базы и отказ на некорректном snapshot без изменения прежних данных.
- Миграции проверены с предыдущих версий IndexedDB.
- Проходят `npm test`, `npm run typecheck`, `npm run check:server`, `npm run check:extension` и `npm run build`.
- MAL, AniList, Shikimori и текущая локальная библиотека проходят регрессионные сценарии.

## Ограничения PR

- Сначала аудит текущей реализации, затем минимальные целевые исправления.
- Не переписывать интеграции без доказанной необходимости.
- Не менять интерфейс ради косметики; приоритет — целостность данных.
- Не удалять и не перезаписывать пользовательские записи ради автоматического устранения дублей.
- Проверять миграции и восстановление на копии данных, оригинальную библиотеку не использовать как тестовый полигон.
